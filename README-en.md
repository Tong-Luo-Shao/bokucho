# Bokucho (墨蝶)

[繁體中文](README.md) · [Download](../../releases) · [Windows guide](PORTABLE_README.md) · [Contributing](CONTRIBUTING.md)

Bokucho is an open-source workbench for translating games. It turns a game's text and images into a reviewable translation project, with AI drafting and people deciding the final text, then builds a patch that players apply in one run and can restore.

It supports **LiveMaker / LiveNovel**, **Ren'Py**, and **RPG Maker MV / MZ / XP / VX / VX Ace**. Bokucho is pre-alpha software, with a Windows desktop app and a Python CLI.

> [!IMPORTANT]
> Bokucho distributes only translation data and patching tools. It does not include, provide, or host any game's executables, cracks, or other unauthorized game data. Translators and players supply original game files from their own legal copies.

## Highlights

- **Complete desktop workflow**: Create projects, extract, translate, review, run quality checks, and release in one app.
- **Major AI providers**: Built-in support for Claude, Gemini, OpenRouter, OpenAI, and DeepSeek, plus any OpenAI-compatible API, including local services such as Ollama and LM Studio.
- **Human work stays**: Machine drafts and reviewed translations are kept apart, and translation runs process untranslated content only.
- **Consistent names**: Project and global glossaries, a prompt library, context, token-aware batching, API key rotation, and rate limits.
- **Source-language filtering**: BCP 47 language tags filter each line before it is sent. Other lines in mixed-language content keep their text and position.
- **Quality checks**: Variables, control codes, formatting, line counts, leftover source text, target language, and glossary usage.
- **Image translation**: PP-OCRv6 detects and reads text, LaMa erases it, and the translation is typeset automatically or edited by hand.
- **No original game files in patches**: Each engine uses compile-on-apply, a mounted plugin, or a native translation folder.
- **Shared GUI and CLI pipeline**: Work interactively, or from scripts and CI.

## Supported engines

| Engine | Extraction and injection | Patch carries translated images | When a player applies the patch |
|---|---|---|---|
| LiveMaker / LiveNovel | Packed or unpacked games, scripts, choices, and text shown through variables | Yes | Injects translations into the player's original, builds a proxy font, and repacks; keeps a backup |
| RPG Maker MV / MZ | JSON data, event text, choices, and plugin note tags | Yes | Installs and enables `Bokucho.js`; original JSON stays unchanged |
| RPG Maker XP / VX / VX Ace | `.rxdata`, `.rvdata`, and `.rvdata2` data, and `.rgssad`, `.rgss2a`, and `.rgss3a` archives | Yes | Rebuilds a packed game's archive or replaces an unpacked game's `Data/` files; keeps a backup. If a VX or VX Ace game ships its own font, characters the translation needs are added to a copy of that font |
| Ren'Py | `game/tl/` translation files generated by the official SDK | No | Installs `game/tl/<language>/` and starts the game in that language; changes no original file |

Every engine's release is the same kind of patch, named `<project>-<source language>2<target language>-patcher.exe`, for example `MyGame-ja2zh-tw-patcher.exe`. Players put it in the game folder and run it; the **還原** (Restore) button in the same EXE undoes it.

KiriKiri / KAG, Unity, and Godot cannot be translated yet.

## Requirements

- **Windows x64**: Use the prebuilt desktop release.
- **A legal copy of the game**: Used to create a project and test patches.
- **An AI interface**: Cloud services need your own API key. Local OpenAI-compatible services usually do not.
- **The Ren'Py SDK**: Needed for Ren'Py projects only; the [official SDK](https://www.renpy.org/latest.html) is free. The desktop app has no field for it yet, so set `sdk_path` under `[engine]` in `project.toml`.
- **An NVIDIA GPU**: Needed for image OCR and automatic erasing only. The app shows the download size and asks before the first download.

## Quick start

### 1. Start

Download `Bokucho-Windows-x64.zip` from [Releases](../../releases), extract it to a writable folder, and run `Bokucho.exe`. Keep the complete folder together. The app starts in Traditional Chinese; switch to English under **Interface language** in **Settings**.

### 2. Create a translation project

1. Click **Create project**.
2. Fill in **Destination** and **Project name**.
3. Under **Game path**, click **Browse** and select the game folder or executable.
4. Confirm the detected game engine.
5. Set source and target languages. Defaults are Japanese (`ja`) to Traditional Chinese (`zh-tw`).
6. Click **Create project** again.

### 3. Configure a translation model

1. Open **Model**.
2. Select a service under **Providers**, then click **Add interface**.
3. Enter **API keys**, select a model, and click **Save**.
4. Click **Test interface** to confirm the connection, then click **Use interface**.

Interfaces are shared by every project. You can save several API keys for one provider, or create an interface for each model.

> [!WARNING]
> Keys are stored in `Resource/credentials.json`. The contents are Base64-encoded, not encrypted. Do not share this file.

### 4. Extract and translate

1. Open **Strings** and click **Extract text**. Extracting again merges new content into existing translations.
2. Before translating, you can open **Glossary** and click **Read the script for names** to settle on one rendering of each name.
3. Return to **Strings**, click **Translate**, then click **Start** in **Translation dashboard**.

Translation can be paused and resumed, and completed batches are saved immediately. If the game mixes languages, select a source language in **Settings**; `und` means no restriction.

### 5. Review drafts

Select an entry under **Strings**, edit its translation, click **Mark reviewed**, then click **Next**. Entries move through these states:

```text
Untranslated -> MT -> Reviewed
```

Translation runs process untranslated content, and reviewed entries stay as they are. To translate an entry again, use the menu beside **Mark reviewed** and choose **Mark untranslated**. For an entry that should not be translated, such as a string the game's scripts use, choose **Mark ignored**; it keeps its original text in the game.

### 6. Translate images (optional)

1. Open **Images** and click **Scan and read text**.
2. Results appear under **Strings** as image text units and use the same translation and review workflow.
3. Return to **Images**, check text boxes and fonts, then click **Erase and typeset**.

See the [Windows guide](PORTABLE_README.md) for model downloads, GPU requirements, storage locations, and bundled fonts.

### 7. Check and release

1. Open **Quality**, review defects and warnings, and use **Go** to open the related entry.
2. Open **Release** and confirm the engine, text-unit count, and untranslated count. LiveMaker projects must select the game text font first.
3. Click **Next**, then **Build now**.
4. The patch is `dist/<timestamp>/<project>-<source>2<target>-patcher.exe`.

Untranslated content is applied as its original text. Before publishing, apply, launch, test, and restore the patch once on a copy of the game.

## Run from source

Requires Python 3.12+ and [uv](https://docs.astral.sh/uv/):

```powershell
git clone https://github.com/Tong-Luo-Shao/bokucho.git
cd bokucho
uv sync --locked --extra dev --extra web
uv run --extra web bokucho-gui
```

Image OCR and automatic typesetting require additional large dependencies:

```powershell
uv sync --locked --extra dev --extra web --extra images
```

## CLI

After installing dependencies, the CLI runs the complete workflow:

```powershell
.\.venv\Scripts\Activate.ps1

bokucho init D:\Translations\my-game --game "D:\Games\MyGame"
cd D:\Translations\my-game

$env:ANTHROPIC_API_KEY = "your-key"
bokucho extract
bokucho build-glossary
bokucho translate --limit 20
bokucho translate
bokucho review
bokucho qa
bokucho build-patch
```

New projects use Claude by default. Gemini uses `GEMINI_API_KEY`, and other OpenAI-compatible interfaces usually use `OPENAI_API_KEY`. You can also create an interface under **Model** in the desktop app; the CLI reads the same project settings.

Run `bokucho --help` for all commands, or `bokucho <command> --help` for options. Main commands:

- Project and text: `init`, `detect`, `extract`, `inject`
- Translation: `build-glossary`, `glossary`, `translate`, `import`, `transform`, `review`
- Validation: `qa`, `verify`
- Images: `images extract --ocr`, `images render`
- Release: `patch-runtime`, `patch-font`, `build-patch`

## Project data

Each translation project is made of regular files that can be managed with Git:

```text
project.toml              Project, engine, model, and transform settings
strings/*.json            Source, translation, state, history, and engine location
glossary.json             Project glossary
images-inventory.json     Image scan results, when using the image workflow
out/                      Local overlays and image drafts
dist/                     Release artifacts
```
